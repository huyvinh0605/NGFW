# M5 source notes

Research date: 2026-10-09. These are upstream facts and references, not evidence
that the lab has these packages or that an M5 feature has passed acceptance.
The brief left `<VYOS_CONFIG_GUIDE_URL>` as a placeholder; this plan resolves it
to the official [VyOS 1.5 configuration guide](https://docs.vyos.io/en/1.5/configuration/index.html).
No VyOS implementation source is used. Decisions in the other documents are
SENTINEL design decisions unless explicitly attributed here.

| ID / section inspected | Source | Key behavior | Design implication |
|---|---|---|---|
| V01 Static / IPv4, alternate tables | [VyOS static](https://docs.vyos.io/en/1.5/configuration/protocols/static.html) | Static next hops and protocol distances are distinct routing concepts. | Preserve M1 metric semantics; do not reinterpret metric as FRR administrative distance. |
| V02 OSPF / general, interface, redistribution, OSPFv3 | [VyOS OSPF](https://docs.vyos.io/en/1.5/configuration/protocols/ospf.html) | OSPFv2 and v3 have separate configuration; area/interface/passive/cost and redistribution are configurable. | Select IPv4 OSPFv2 only; v3 waits for IPv6 security acceptance. The separate guessed `ospf3.html` URL failed; v3 is in this page. |
| V03 BGP / neighbors, AF, route policy | [VyOS BGP](https://docs.vyos.io/en/1.5/configuration/protocols/bgp.html) | ASN/peer/AF policy and maximum paths exist; VyOS documents a backward-compatible default for eBGP policy requirements. | SENTINEL explicitly requires import/export filtering, independent of vendor defaults. |
| V04 BFD / peers and timers | [VyOS BFD](https://docs.vyos.io/en/1.5/configuration/protocols/bfd.html) | Peer timers and protocol integration are configurable. | Conservative lab defaults; no submillisecond convergence claim. |
| V05 Prefix lists / ge/le | [VyOS prefix lists](https://docs.vyos.io/en/1.5/configuration/policy/prefix-list.html) | Ordered address-family-specific prefix matching. | Typed prefix rules, canonical CIDRs, deterministic ordering. |
| V06 Route maps / matches, local preference, MED | [VyOS route maps](https://docs.vyos.io/en/1.5/configuration/policy/route-map.html) | Routing attributes and selection are separate from packet filtering. | New routingpolicy model; no SecurityPolicy reuse. |
| V07 PBR / table actions | [VyOS route policy](https://docs.vyos.io/en/1.5/configuration/policy/route.html) | Policy routing can select routing tables. | Evaluated; arbitrary PBR is deferred to avoid introducing unowned tables/marks. |
| V08 VRF / table and membership | [VyOS VRF](https://docs.vyos.io/en/1.5/configuration/vrf/index.html) | VRF binds interfaces and routing tables. | Requires explicit session/correlation isolation, so outside core M5. |
| V09 WAN / warning, flow selection, failover | [VyOS WAN load balancing](https://docs.vyos.io/en/1.5/configuration/loadbalancing/wan.html) | Its custom routing/firewall scheme conflicts with dynamic routing; established sessions do not automatically migrate. | Choose architecture C: FRR/Linux routed ECMP and failover; no copied WAN-LB machinery or automatic conntrack flush. |
| V10 HAProxy / service, backend, TLS, rules | [VyOS HAProxy](https://docs.vyos.io/en/1.5/configuration/loadbalancing/haproxy.html) | Distinguishes listeners, backend algorithms and HTTP/TLS delivery rules. | Use native HAProxy; explicit binds and verified upstream TLS are stricter than permissive options shown in VyOS. |
| V11 HA / VRRP, preemption, groups, virtual servers | [VyOS HA](https://docs.vyos.io/en/1.5/configuration/highavailability/index.html) | Router redundancy and IPVS virtual servers are distinct capabilities. | VRRP core; IPVS evaluated but deferred. |
| V12 Conntrack sync / active-backup | [VyOS conntrack sync](https://docs.vyos.io/en/1.5/configuration/service/conntrack-sync.html) | Kernel connection synchronization is a separate HA facility. | No stateful failover claim from VRRP alone. |
| F01 Integrated configuration | [FRR 8.4 basic](https://docs.frrouting.org/en/stable-8.4/basic.html#config-methods) | Integrated frr.conf is dispatched to interested daemons; command logging can expose passwords. | Generated root-owned config and no command logging; Running is authority, never `write memory`. |
| F02 Delta reload | [FRR reload](https://docs.frrouting.org/en/stable-8.4/frr-reload.html) | `--test` emits a delta; `--reload` executes it against daemons. | A diff is not a syntax validator or atomic transaction; retain previous artifacts for compensation. |
| F03 Offline CLI syntax checking | [FRR 8.4.4 vtysh_main.c](https://raw.githubusercontent.com/FRRouting/frr/frr-8.4.4/vtysh/vtysh_main.c) (`case 'C'`, dryrun branch) | `vtysh -C -f file` reads configuration without connecting to running daemons. | Use as pre-mutation syntax gate; runtime semantic verification remains necessary. |
| F04 Zebra route filtering | [FRR Zebra](https://docs.frrouting.org/en/stable-8.4/zebra.html#zebra-route-filtering) | Protocol-specific route maps filter installation into the kernel; route-map processing can be delayed. | Reserve M1 exact prefixes with generated BGP/OSPF FIB filters and wait for readback before ownership changes. |
| F05 OSPF configuration and Showing Information | [FRR OSPFv2](https://docs.frrouting.org/en/stable-8.4/ospfd.html) | Interface controls and neighbor/interface/route JSON queries exist. | Use bounded JSON; protocol convergence is separate from config apply success. |
| F06 BGP peers/policy/route display | [FRR BGP](https://docs.frrouting.org/en/stable-8.4/bgp.html) | JSON distinguishes accepted peer routes, advertised routes and pre-policy received routes. | Default endpoint shows accepted routes; raw received view requires an explicit available capability/soft-reconfiguration budget. |
| F07 BFD profiles, BGP/OSPF integration | [FRR BFD](https://docs.frrouting.org/en/stable-8.4/bfd.html) | FRR notifies routing protocols when BFD changes; OSPF can create monitored peers. | FRR owns BFD state and route reactions; SENTINEL observes. |
| F08 Route-map processing | [FRR route maps](https://docs.frrouting.org/en/stable-8.4/routemap.html) | Ordered permit/deny matching and supported attribute setters. | Bounded typed subset, explicit final deny; reject freeform commands and recursive calls. |
| H01 Syntax, reload, Unix statistics | [HAProxy 2.8 management](https://docs.haproxy.org/2.8/management.html) (`Starting`, `Master CLI`, `show stat json`, `show schema json`) | Syntax check, master-worker reload and schema-described JSON statistics exist. | Validate before reload, observe worker readiness, never parse formatted console tables. |
| H02 Delivery/TLS/algorithms | [HAProxy 2.8 configuration](https://docs.haproxy.org/2.8/configuration.html) (`balance`, `bind`, `server`, `http-check`, `master-worker`) | Backend delivery and TLS controls are native features. | Render a small allowlisted grammar; HAProxy cannot authorize security policy. |
| K01 VRRP/FIFO/health/IPVS | [Keepalived 2.2.8 configuration manpage](https://raw.githubusercontent.com/acassen/keepalived/v2.2.8/doc/man/man5/keepalived.conf.5.in) (`vrrp_notify_fifo`, `json_version`, `nopreempt`, script security, virtual_server) | Structured FIFO notifications, optional D-Bus, JSON v2 and tracked health are documented; nopreempt needs non-MASTER initial state. | Use BACKUP start, FIFO plus JSON snapshot; no arbitrary Candidate scripts. |
| K02 Syntax and signals | [Keepalived 2.2.8 command manpage](https://raw.githubusercontent.com/acassen/keepalived/v2.2.8/doc/man/man8/keepalived.8.in) (`--config-test`, `--signum`, JSON) | Syntax test has distinct failure statuses; JSON signal dumps state to configured build temporary directory. | Reject every nonzero validation exit; protected shared dump path and PID-checked signal. Public website manpage returned 404; this tagged upstream manual replaces it. |
| L01 Routing tables, proto, multipath | [ip-route manual](https://man7.org/linux/man-pages/man8/ip-route.8.html) | Table/protocol/metric/nexthops are distinct route attributes. | Protocol is provenance metadata, not sufficient isolation for route replacement. |
| L02 Policy routing | [ip-rule manual](https://man7.org/linux/man-pages/man8/ip-rule.8.html) | RPDB has ordered selectors and table actions. | No extra RPDB writer in core M5. |
| L03 VRF | [Linux VRF](https://docs.kernel.org/networking/vrf.html) (`Setup`, `Applications`) | Interface enslaving moves connected/local routes and can remove dependent routes; sockets require VRF-aware handling. | Deferral protects M1 lifecycle and M2–M4 identity/socket assumptions. |
| L04 ECMP and reverse-path filtering | [Linux IP sysctl](https://docs.kernel.org/networking/ip-sysctl.html) (`fib_multipath_hash_policy`, `rp_filter`) | Multipath hash policy and source validation affect path selection; stable next-hop distribution across kernel versions is not guaranteed. | Pin lab kernel evidence; no hard distribution or seamless-session promise; record any scoped sysctl changes. |
| C01 Stateful HA | [conntrack-tools manual](https://conntrack-tools.netfilter.org/manual.html) (state synchronization, internal/external cache, active-backup) | conntrackd provides kernel-state synchronization/recovery. | It cannot replicate M2 policy authority, M3 verdicts, M4 HTTP state or HAProxy TCP buffers. |
| P01 Ubuntu package families | [noble-updates networking packages](https://packages.ubuntu.com/eu/noble-updates/all/net/), [Keepalived noble](https://packages.ubuntu.com/noble/keepalived) | Available baseline families include FRR 8.4.4, HAProxy 2.8 and Keepalived 2.2.8. | Pin actual installed revisions/hashes at T01; these web listings do not prove VM installation. |
| L05 Probe socket capabilities | [Linux 6.8 sock.c, sock_bindtoindex_locked](https://raw.githubusercontent.com/torvalds/linux/v6.8/net/core/sock.c) | NET_RAW check applies when a socket is already device-bound; the initial binding of a fresh socket follows a different path. | One fresh TCP socket/one device binding per probe; verify under actual engine sandbox at T01; no added capability or unbound fallback. |
| F09 FRR process privileges | [FRR 8.4.4 zebra main.c](https://raw.githubusercontent.com/FRRouting/frr/frr-8.4.4/zebra/main.c), [privs.c](https://raw.githubusercontent.com/FRRouting/frr/frr-8.4.4/lib/privs.c), [unit template](https://raw.githubusercontent.com/FRRouting/frr/frr-8.4.4/tools/frr.service.in) | Zebra declares NET_ADMIN, SYS_ADMIN and NET_RAW; supervisor and daemon privilege drop are distinct. | Do not claim the stock package needs only NET_ADMIN; audit a separate FRR unit profile, never enlarge engine/API capabilities. |
